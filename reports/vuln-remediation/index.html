01Group by software, not by CVE

Twenty findings on one device usually come from only 3–5 programs: an old Chrome, Java, Adobe Reader, 7-Zip, WinRAR, Zoom, VLC or Office. Updating one program can close ten or more CVEs at once.

  • Export your scanner report and pivot it by product + version, not by CVE or host.
  • Typically about 10 products cause about 80% of the findings across the fleet. Fix those first.
  • Defender for Endpoint (“Software inventory” / “Remediation”) and Tenable (“Solutions”) already provide this grouping.

02Prioritise: not all findings are equal

Work through findings in this order:

  1. 1
    On the CISA KEV listKnown Exploited Vulnerabilities: attackers are already using these.
  2. 2
    Internet-facing serversWeb servers, VPN gateways, remote access, anything reachable from outside.
  3. 3
    High EPSS scoreExploit Prediction Scoring System: the likelihood of exploitation in the next 30 days.
  4. 4
    CVSS Critical / HighBase score 7.0 and above.
  5. 5
    Everything elseHandled in the normal monthly patch cycle.

03Automate patching

This is the biggest win. In most cases you don't need to uninstall and reinstall: most installers upgrade in place. Push updates centrally.

AreaTools
Windows OS / OfficeWSUS, Intune / Windows Autopatch, SCCM (MECM)
Third-party appsPatchMyPC (plugs into Intune/SCCM), ManageEngine Patch Manager Plus, Action1 (free up to 200 endpoints), NinjaOne, Ivanti
No budgetwinget or Chocolatey scripts pushed via GPO, Intune or a scheduled task
Linuxunattended-upgrades / dnf-automatic, Ansible
PowerShell · upgrade all winget-managed apps silently
winget upgrade --all --silent --accept-package-agreements --accept-source-agreements --include-unknown

Push it as a startup script or a scheduled task running as SYSTEM.

04Remove software nobody needs

Many findings come from software nobody uses: old Java, Flash leftovers, old runtimes installed side by side, trial software.

  • Get an inventory of installed software across all devices from your scanner, Intune or SCCM.
  • Script removal of old versions and unapproved apps. Old Java versions often stay installed next to the new one and keep getting flagged.
PowerShell · remove Java builds older than a given version
Get-Package -Name "Java*" |
  Where-Object Version -lt "8.0.431" |
  Uninstall-Package -Force

Set the version threshold to your current approved build, and test on a pilot group before you deploy it to every device.

05Stop it from coming back

  • Approved software list. Define a standard set of apps for the company.
  • Remove local admin rights so users can't install software on their own.
  • Turn on auto-update through policy for Chrome, Edge, Firefox, Adobe Reader and Zoom.
  • Application control with AppLocker or WDAC if you want to go further.
  • Standard image. For very messy machines, reimaging is often faster than cleaning up 20 findings.
  • End-of-life OS. Unpatched Windows 10 and Server 2012 can't be patched clean. Upgrade or replace them.

06Make it a process

  • Monthly patch cycle, e.g. one week after Patch Tuesday.
  • Rollout rings. Test on 5–10% of devices (IT staff first), then deploy to everyone after a few days.
  • Exceptions register. If a legacy app needs an old version, document the accepted risk and add compensating controls such as network isolation.
  • Rescan after fixing. Use authenticated (credentialed) scans so stale results and leftover registry entries don't show up as false findings.

07Suggested first two weeks

  1. Days 1–2Export the scan results and pivot by software to get your top 10 offenders.
  2. Days 3–7Push updates or removals for those 10 to a pilot group, then to everyone.
  3. Day 8Rescan. Expect the total finding count to drop by roughly 60–80%.
  4. Days 9–14Set up automated third-party patching so the count stays low.
