## 1. Goal of the session

Migrate the **HitachiDispatch** app (a .NET MAUI Android app, project `GpsSync`) off **Supabase
cloud** onto a **self-hosted SQL Server backend** that runs on localhost first, then a cloud later.
The presenting symptom: **login / create-user kept failing with "network" errors** when running
locally.

Key decisions captured up front:
- Run target: **Android emulator**.
- Backend end state: **SQL Server is a hard requirement** (not just "off cloud").
- Backend location: **new `/server` folder in this repo**, SQL Server in **Docker**.
- Build machine: **Windows + Visual Studio 2022**.
- Code transfer: **push a branch to GitHub**.

---

## 2. Diagnosis (why login failed)

1. The app is a **client only** — it used the **Supabase C# SDK** (GoTrue auth + PostgREST) for
   everything. It spoke Supabase's HTTP protocols, which **SQL Server does not serve**. So "point
   it at SQL Server" was never a config change.
2. On this machine there was **no backend running at all** (no Supabase, no SQL Server) — verified
   with `ss`/`docker ps`. The app was reaching for a server that didn't exist.
3. Secondary Android issues that would have bitten next: emulator can't reach `localhost` (needs
   `10.0.2.2` or a routable IP), and Android **blocks cleartext HTTP** by default.
4. `AppConfig.cs` (holding the backend URL) was **missing from the repo** — the app wouldn't even
   compile as committed.

Conclusion: the only correct path was to **build the replacement backend** (Path B).

## 3. What was built — a working SQL Server backend

**`/server/GpsSync.Api`** — ASP.NET Core (**.NET 10**) Web API + **SQL Server 2022** (EF Core,
code-first) + **JWT auth** (access + rotating refresh tokens). Runs on `http://0.0.0.0:5080`,
auto-applies EF migrations and seeds an admin on startup.

- SQL Server runs in Docker (container `geo-sqlserver`, port 1433).
- Tables: `profiles`, `dispatch_jobs`, `gps_pings`, `refresh_tokens`, `password_reset_codes`, plus
  ASP.NET Identity tables.
- Seeded admin for testing: **`admin@local.test` / `Admin!23`**.
- Secrets (SA password, JWT key) are **not** in committed config — supplied via env vars
  (`ConnectionStrings__Default`, `Jwt__Key`) from a git-ignored `server/.env`; `appsettings.json`
  ships with `__SET_VIA_ENV__` placeholders. `server/.env.example` documents the shape.
- Run/test instructions: **`server/README.md`**.

### Endpoints (all verified via curl)
| Area | Endpoints |
|---|---|
| Auth | `POST /auth/register\|login\|refresh\|logout`, `GET /auth/me`, `PATCH /auth/user`, `POST /auth/forgot-password\|reset-password` |
| Profiles | `GET /profiles` (admin), `GET\|PATCH /profiles/{userId}` |
| Jobs | `GET /jobs`, `POST /jobs` (admin), `PATCH /jobs/{id}`, `DELETE /jobs/completed` (admin) |
| GPS | `POST /gps`, `GET /gps`, `GET /gps/latest` (admin), `DELETE /gps` (admin) |
| Users | `DELETE /users/{userId}` (admin — full engineer removal) |
| Health | `GET /health` |

Authorization rule throughout: a user acts on their **own** data; **admins** act on anyone.
Engineers are server-side **forced** to their own scope on list endpoints.

## 4. App-side migration (four slices)

A new `Services/BackendClient.cs` (`IBackendClient`) wraps `HttpClient`: JWT storage in
`SecureStorage`, transparent refresh-on-401, error messages mapped to the app's existing friendly
text, and `EnsureSessionLoadedAsync` for background services. `AppConfig.ApiBaseUrl` points at the
backend. `MauiProgram` registers the client.

**Slice 1 — Auth + profiles:** `LoginViewModel`, `RegisterViewModel`, `SplashViewModel` (session
restore + device check), `SettingsViewModel`. Android `network_security_config.xml` added to permit
cleartext HTTP to the dev host.

**Slice 2 — Jobs:** `AdminJobsViewModel`, `JobsViewModel`, `JobItem`, `JobNotificationService`,
`Delegates/MyJob.cs`, and the central `MainViewModel` (profile load, punch in/out, punch-out guard,
device-session check, job badges).

**Slice 3 — GPS:** `Delegates/MyGpsDelegate.cs` (push pings + offline-queue drain),
`GpsWatchdogService.cs`, `Delegates/MyJob.cs` (offline sync restored), `MapViewModel.cs` (admin live
map + **job dispatch**), `EngineerStatusViewModel.cs` (status board, rename, remove-engineer).
Deleted dead Supabase model classes `ProfileRecord`/`DispatchJobRecord`/`GpsPingRecord`.

**Slice 4 — Password reset + full Supabase removal:** `ForgotPasswordViewModel` → backend 6-digit
code flow. Deleted `ResetPasswordViewModel`/`ResetPasswordPage` and `SupabaseTokenRefreshService`.
Removed the Supabase client registration, `AppConfig.SupabaseUrl/Key`, and the **`Supabase` NuGet
package**. Verified **zero** Supabase references remain in app code.

**Outcome: the app has no dependency on Supabase.** Every feature runs on the SQL Server backend.

## 8. How to build & run (Windows + emulator)

1. Ensure the API is up on `flux` (see `server/README.md`; secrets from `server/.env`), and
   Tailscale is up on the Windows machine.
2. `git fetch origin && git checkout migrate/sqlserver-auth-profiles`.
3. Install the VS 2022 **".NET MAUI development"** workload (Android SDK + emulator + JDK).
4. Open `GpsSync.csproj` (NOT the `/server` project), pick an Android emulator, press F5.
5. Log in with `admin@local.test / Admin!23`, or register a new engineer.
6. Password-reset codes appear in the API log on `flux` (`tail -f server/api.log`).
